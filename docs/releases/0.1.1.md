# PURE RGB 0.1.1

本次正式发布使用 **build 7**，替换此前已撤回的 0.1.1 安装包。支持 Apple 芯片 Mac，要求 macOS 14 或更新版本。

## 新特性

- 输入明确分为「拜耳 RGB · 三张 RAW」和「单色 RGB · 三张 RAW」，另保留单张黑白负片。单色流程直接读取传感器样本，使用 RAW 黑白位归一化，并支持核对 R、G、B 文件顺序。
- 导入后自动识别有效画面，以其中心约 **80% 面积**作为默认密度测量范围。识别失败时，画面中央提示手动绘制矩形，再继续转换。
- 启动时询问是否载入上次任务；选择「否」可进入独立空白项目，原项目继续保留。
- 高光参考区、作用区和人物／中间调保护区独立管理。作用区内按亮度平滑筛选高光，自动柔化边缘，并提供额外羽化半径调整。
- 窗口背景使用 SwiftUI `.ultraThinMaterial`，无法加载时回退到 AppKit 材质。

## 修复

- 修复进入高光绘制后显示错误负像、方向改变，以及裁切后坐标不一致的问题。默认保持当前正像，可切换查看完整源画面。
- 高光参考可以独立于密度测量范围绘制；新绘制的密度区默认使用矩形，已保存的形状继续保留。
- 修复局部高光处理留下矩形痕迹、作用区与保护区混用，以及切换照片／工具后未完成笔划残留的问题。
- 高光算法变化后明确提示重新生成完整版本；旧成片保留，除尘审核需要按新版本重新确认。
- 改进旧项目平场身份和测量快照兼容、预览运行时资源定位，以及导入到测量步骤的提示与衔接。
- 关闭并重新开启高光找回时保留参考区、作用区、保护区和参数。

## 性能与资源利用

- 持久 RAW 解码缓存可跨会话复用，读取时校验来源、配方、校准和解码版本。
- 按可用内存与画幅安排 RAW 解码和批量导出，导出最多同时运行 3 个任务；内存不足或超大画幅回退串行。
- 空闲预热在前台操作开始时让出资源，减少预热与导入、预览、渲染、显示争用。
- 复用密度测量和显示缓存，分块处理高光保护蒙版，减少临时数组及重复统计。

开发期间同一台 M1 Max、40 组不同真实三色 RAW 的简单 Native 导出对照为 162.44 → 150.15 秒，RGB16 像素与 ICC 一致。该对照每版仅一次、固定顺序、关闭持久解码缓存，不含平场、高光或除尘，且早于最终高光修复，不能作为 build 7 的通用提速比例。

96MP 冷预览低于 5 秒的目标尚未达成，大画幅仍可能占用约 10 GiB 内存。本版未将实测较慢的 libvips 路径设为默认，也未宣称完整渲染已迁移到 GPU。

## 更新通道

正式版本通过 [GitHub Releases latest](https://github.com/easonzhangbin/PURERGB/releases/latest) 提供。0.1.1 启动约 2 秒后异步检查，运行期间每 24 小时再检查一次；设置中的「通用 → 检查更新」可手动查询。发现新版时显示「查看更新」，离线时不打断工作。**应用不会自动下载或安装。**

0.1.0 用户请在设置中手动检查更新并下载。已经装过被撤回的旧 0.1.1 或较早测试包的用户，请重新下载安装本页 build 7；旧版仅比较版本号，无法识别同为 0.1.1 的替换包。

## 下载与限制

下载 `PURE-RGB-0.1.1-macos-arm64.zip`，解压后把 `PURE RGB.app` 放入「应用程序」。包内版本号为 0.1.1，构建号为 7，SHA-256 见附件 `SHA256SUMS-macos-arm64.txt`。应用使用临时签名，尚未通过 Apple 公证；首次打开可参照 [Apple 官方说明](https://support.apple.com/en-us/102445)。

单色 RGB 暂不支持 RAW 内嵌镜头矫正；P45 原始 IIQ 黑白位不可靠时需使用带可靠黑白位标记的单色 DNG。Nikon CMS 资源需用户本机自备，PURE Neg 除尘后端需单独安装。详见[操作手册](https://github.com/easonzhangbin/PURERGB/blob/v0.1.1/docs/OPERATING_MANUAL.zh-CN.md)。

目录管理、图片库管理和 PURE Neg 观片器列为 **0.1.2 待开发／待引入内容**。
